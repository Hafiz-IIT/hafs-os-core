# Portfolio Demo Plan

The portfolio needs visible evidence, not only source code.

## Demo hierarchy

### Level 1 — deterministic terminal demonstrations
Every research repository should expose one command that loads a tiny example, runs the core mechanism, prints an interpretable result and exits successfully.

### Level 2 — experiment artifacts
Flagship research repositories should expose sample input, sample output, benchmark summaries, architecture diagrams and limitations.

### Level 3 — interactive applications
Projects that genuinely contain an application should be presented with a live UI only when a real runnable/deployed application exists.

Priority historical candidates:
1. Smart City Management
2. Restaurant Order Management

Priority research candidates for lightweight interactive demos:
1. EXIM Evidence-Gated Autonomy
2. EXIM Document Truth
3. Secure Document RAG
4. Safe RL Action Gate

## Demo integrity
Never create a fake screenshot or fictional deployment URL.

A demo may be a reproducible terminal run, generated benchmark artifact, local web application or real deployment. The README must say which one it is.
